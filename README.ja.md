# java-programming-retrospective

1年次相当のJavaの課題を、2学期あとに作り直したものです。

交換留学中にJavaの入門科目を履修し、2本のプログラムを提出しました。科目の評価は **67/100** でした。このリポジトリはその提出物ではありません。**同じ2つの問題に、今の習慣で戻ったらどうなるか**です。科目で配られた補助ライブラリを外し、論理を入力と出力から切り離し、データは配られたものではなく自分で作り、テストが0件だったところに64件書きました。

> **ここにあるコードは採点されていません。**上の評価は当時の科目に対するものです。このリポジトリの中身はすべて後から、このリポジトリのために書いたものです。元の提出物も講義資料も公開していません。

技術文書の本体は英語の [README.md](README.md) です。この文書は要点だけをまとめたものですので、詳細はリンク先をご覧ください。

## 当時提出したもの

コンソールで動く2本です。1本目は**重量の換算表**で、質量を読み、キログラムに直し、選んだ天体の重力でもう一度換算して、小さなデータファイルの内容も含む表を出力します。2本目は**ドット絵**で、文字の格子を読み、各文字が何を表すかを文字コードの計算で決め、2つの倍率で（片方は鏡像で）窓に描き、一部を喫水線の下に隠します。

どちらも動いて、どちらも採点されました。**そしてどちらにもテストが1件もありませんでした。**読み返したことが、このリポジトリの出発点です。

## 当時と今

| 当時 | 今 | なぜ意味があるのか |
|---|---|---|
| 入力と描画をすべて学科の補助ライブラリで | `BufferedReader`・`Files`・`ImageIO` | 科目の中にしか存在しないライブラリなしで、どこでもコンパイルできる |
| 解析の失敗を空のブロックで握り潰す | 読めなかった行を、行番号と理由を持つ `ParseProblem` として返す | データファイルの打ち間違いで表から1行が黙って落ちていた。今は報告され、終了コードも変わる |
| データファイルの書式を決め打ち | 3つの書き方を受け入れ、それ以外は報告 | 目録は人が書くものなので、そもそも不揃いになる |
| 130×130の格子を無検査で読む | 格子の寸法を検証し、長さの揃わない行は行番号つきで拒否 | 1文字足りないだけで絵全体が黙ってずれていた |
| if/elseの連なりの中の裸の数値で分類 | 順序があり名前が付いた、設定ファイル駆動の規則集合 | 規則の順序が絵を変える。その事実をテストで固定した |
| 窓に直接描画 | 素のピクセル配列に描き、ファイル形式は最外縁に置く | 1ピクセルずつ検証できる。画面表示を必要としない |
| データは科目から支給 | このリポジトリの符号化器が作った標本データ | 標本が自分のものになり、往復のテストで復号器の正しさを示せる |
| テストなし | 64件のテスト、checkstyle、spotless、CI | 上の作り直しは、これがあって初めて安全にできる |

## 絵について

`data/sailboat.map` が標本スプライトの読める形で、`data/sailboat.txt` は同じ絵を、このリポジトリの符号化器で雑音のような見た目に変換したものです。**後者を復号すると前者に完全に戻ります。**その往復がテストになっています。実際の出力例と画像は [The picture](README.md#the-picture) にあります。

## 動かし方

JDK 17以降と Maven が必要です。

```bash
mvn verify                      # コンパイル、64件のテスト、checkstyle、書式検査
java -jar target/java-programming-retrospective-1.0.0.jar weights data/gravity.txt 150
java -jar target/java-programming-retrospective-1.0.0.jar scene data/sailboat.txt scene.png
```

`weights` は終了コード `1` で終わります。標本データに、読めない行を1行だけ意図的に入れてあるためです。

## 構成

両方のパッケージを形づくっている規則は1つです。**外の世界に触れるものは、最外縁に単独で置く**というものです。画像ライブラリを知っているクラスは `PngWriter` だけ、`System.out` を知っているクラスは `Main` だけです。他のクラスは値を受け取って値を返します。64件のテストが、ファイルも窓もディスク上の準備データもなしに1秒以内で終わるのはそのためです。

## 作り直して分かったこと

- **空の `catch` は、情報を捨てるという判断です。**元の実装で最も悪い習慣で、データが誤っているまで表に出ません。直し方は「代わりに投げる」ことではなく、**失敗を、呼び出し側が表示できる値にする**ことです
- **テストできないコードは、たいてい難しいコードではなく分け方の悪いコードです。**船を描くこと自体は検証が難しくありません。**窓に直接**描いていたことが検証を妨げていたので、クラスを1つ動かすと解決しました
- **名前のない定数は、待機中のバグです。**分類の規則は元の実装でも正しかったのですが、なぜ正しいのかを説明できませんでした。「最初に一致したものが勝つ」という一文とともにファイルに出したことが、実際の修正です
- **逆向きを書くと、元がテストできるようになります。**符号化器はどこからも必要とされていません。復号器を検査するために存在していて、「たぶん合っている」プログラムを、示せるプログラムに変えました

## 制約

- スプライトの描画は整数倍でセル単位です。回転も混色も輪郭の平滑化もありません。手抜きではなく、これが狙いの見た目です
- 目録の解析器が受け入れるのは、上に書いた3つの書き方だけです。4つ目には4つ目のパターンが必要で、一般的な文法はありません
- 文の形の検出は英語だけです
- `Material` は固定の列挙型です。素材を足すには規則ファイルだけでなく列挙型の編集も必要になります。色と意味を隣に置くことを優先しました

## ここに置いていないもの

講義資料は一切ありません。課題文、講義の例、小テスト、模範解答、学科の補助ライブラリ、演習で配られたデータファイルのいずれもありません。元の提出物も、そのままの形でも編集した形でも公開していません。`src/` と `data/` の中身は、すべてこのリポジトリのために書いたものです。
